## Executive Summary

This implementation plan details the approach for Story 1.6, which transforms the placeholder HomeScreen into a fully functional Game Boy-inspired dashboard. The story has two major components:

1. **Combat Character Selection** - A one-time choice between "Sean" and "Mary" combat characters
2. **Home Screen Dashboard** - The main app hub displaying user stats, avatar, progress rings, and navigation

### Key Design Decisions

- **LCD Screen-Only Design**: All UI content fits within the 329×584pt virtual LCD area
- **Shell Area Stats**: Fitness metrics displayed on the Game Boy shell hardware area (below LCD)
- **Tab Navigation**: Bottom tab bar for Home, Battle, Profile, Settings
- **Progress Visualization**: Dual progress rings (daily/weekly) + momentum/streak bar
- **Quest Cartridge Button**: Retro-styled CTA for entering combat mode

#### 6.1 Profile Service

**File:** `apps/mobile-shell/src/services/profileService.ts`

```typescript
export const fetchUserProfile = async (userId: string): Promise<UserProfile | null> => {
  const { data, error } = await supabase
    .from('user_profiles')
    .select('*')
    .eq('id', userId)
    .single();

  if (error) {
    console.error('Failed to fetch user profile:', error);
    return null;
  }

  return data;
};

export const updateUserProfile = async (
  userId: string, 
  updates: Partial<UserProfile>
): Promise<boolean> => {
  const { error } = await supabase
    .from('user_profiles')
    .update(updates)
    .eq('id', userId);

  if (error) {
    console.error('Failed to update user profile:', error);
    return false;
  }

  return true;
};

export const updateCombatCharacter = async (
  userId: string,
  character: 'sean' | 'mary'
): Promise<boolean> => {
  return updateUserProfile(userId, { combat_character: character });
};
```

```typescript
  setWeeklySteps: (steps: number) => void;
  calculateWeeklySteps: () => Promise<void>;
}

// In store implementation:
setWeeklySteps: (steps) => set({ weeklySteps: steps }),

calculateWeeklySteps: async () => {
  const userId = useAuthStore.getState().user?.id;
  if (!userId) return;

  const { data } = await supabase
    .from('user_steps')
    .select('step_count')
    .eq('user_id', userId)
    .gte('date', getStartOfWeek())
    .lte('date', getEndOfWeek());

  const total = data?.reduce((sum, day) => sum + day.step_count, 0) || 0;
  set({ weeklySteps: total });
},
```

## Risk Assessment & Mitigation

### High Risk

**Risk:** ProgressRing performance on low-end devices  
**Impact:** Janky animations, dropped frames  
**Mitigation:** 
- Use `react-native-skia` instead of SVG if performance issues arise
- Implement `React.memo` to prevent unnecessary re-renders
- Throttle progress updates to 1 update per second

### Medium Risk

**Risk:** Weekly steps calculation complexity  
**Impact:** Incorrect weekly totals, timezone issues  
**Mitigation:**
- Use UTC timestamps consistently
- Add unit tests for edge cases (week boundaries, DST transitions)
- Cache weekly totals in `user_profiles.weekly_steps` column

**Risk:** Navigation integration with existing onboarding flow  
**Impact:** User stuck in onboarding, can't reach HomeScreen  
**Mitigation:**
- Add `onboarding_completed` flag to `user_profiles` table
- Conditional navigation: if `onboarding_completed === false`, show onboarding; else show HomeScreen
- Add "Skip for now" option on CharacterSelectionScreen

### Low Risk

**Risk:** MagicPath.ai prompts don't generate pixel-perfect designs  
**Impact:** Manual adjustments needed after export  
**Mitigation:**
- Use prompts as starting point, refine in code
- Reference existing atomic components for consistency
- Iterate on MagicPath.ai prompts based on initial results
