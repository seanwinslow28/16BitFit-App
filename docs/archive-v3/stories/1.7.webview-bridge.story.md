## Technical Architecture

### Combat Transition Integration

This story implements the WebView and bridge components that are orchestrated by the **Combat Transition Pipeline** defined in [docs/architecture.md](../architecture.md#combat-transition-pipeline).

The Combat Transition Pipeline coordinates:
1. **Pre-mounting** the WebView (hidden) during PHASE 1
2. **PREPARE_COMBAT** message to initialize Phaser before video transition
3. **READY** message from Phaser to signal combat is prepared
4. **Orientation lock** timing between VIDEO A and VIDEO B
5. **WebView reveal** after VIDEO B completes

### Hybrid Velocity Bridge Protocol

**Binary Message Format:**
```typescript
interface BridgeMessage {
  type: BridgeMessageType;
  payload?: any;
  timestamp: number;
  id: string;
}

enum BridgeMessageType {
  // RN → Phaser (Combat Transition)
  PREPARE_COMBAT = 'PREPARE_COMBAT',  // Pre-mount initialization
  INIT_GAME = 'INIT_GAME',
  START_COMBAT = 'START_COMBAT',
  PLAYER_INPUT = 'PLAYER_INPUT',
  PAUSE_GAME = 'PAUSE_GAME',
  RESUME_GAME = 'RESUME_GAME',
  ABORT_COMBAT = 'ABORT_COMBAT',      // App backgrounded during transition

  // Phaser → RN (Combat Transition)
  READY = 'READY',                     // Phaser is ready for combat
  GAME_READY = 'GAME_READY',
  COMBAT_COMPLETE = 'COMBAT_COMPLETE',
  HEALTH_CHANGED = 'HEALTH_CHANGED',
  ROUND_END = 'ROUND_END',
  COMBAT_TIMEOUT = 'COMBAT_TIMEOUT',   // 10-minute timeout reached
}
```

### 2. Bridge Service (MessagePack + Base64)

**File:** `apps/mobile-shell/src/services/bridgeService.ts`

> **⚠️ Serialization Format (Deep Think 2025-12-28):**
> **Use MessagePack + Base64, NOT JSON.** JSON.parse is a bottleneck on the JS thread. MessagePack is binary (faster). postMessage only accepts strings, so Base64 encoding is required.

```typescript
import { encode, decode } from '@msgpack/msgpack';
import { Buffer } from 'buffer';

class BridgeService {
  private messageQueue: BridgeMessage[] = [];
  private listeners: Map<BridgeMessageType, ((payload: any) => void)[]> = new Map();
  private webViewRef: React.RefObject<WebView> | null = null;
  private pendingPromises: Map<string, { resolve: Function; reject: Function }> = new Map();

  setWebViewRef(ref: React.RefObject<WebView>): void {
    this.webViewRef = ref;
  }

  send(type: BridgeMessageType, payload?: any): void {
    const message: BridgeMessage = {
      type,
      payload,
      timestamp: Date.now(),
      id: generateUUID(),
    };

    // Encode as MessagePack, then Base64 for string transport
    const binary = encode(message, { useBigInt64: true });  // CRITICAL: BigInt support
    const base64 = Buffer.from(binary).toString('base64');

    this.webViewRef?.current?.postMessage(base64);
  }

  // Wait for a specific message type (with timeout)
  waitFor(type: BridgeMessageType, timeoutMs: number = 5000): Promise<any> {
    return new Promise((resolve, reject) => {
      const timeoutId = setTimeout(() => {
        reject(new Error(`Timeout waiting for ${type}`));
      }, timeoutMs);

      const handler = (payload: any) => {
        clearTimeout(timeoutId);
        this.off(type, handler);
        resolve(payload);
      };

      this.on(type, handler);
    });
  }

  on(type: BridgeMessageType, callback: (payload: any) => void): void {
    if (!this.listeners.has(type)) {
      this.listeners.set(type, []);
    }
    this.listeners.get(type)!.push(callback);
  }

  off(type: BridgeMessageType, callback: (payload: any) => void): void {
    const listeners = this.listeners.get(type);
    if (listeners) {
      const index = listeners.indexOf(callback);
      if (index > -1) listeners.splice(index, 1);
    }
  }

  // Handle incoming messages from WebView
  handleMessage(event: WebViewMessageEvent): void {
    try {
      // Decode from Base64 → MessagePack
      const binary = Buffer.from(event.nativeEvent.data, 'base64');
      const message = decode(binary, { useBigInt64: true }) as BridgeMessage;

      const listeners = this.listeners.get(message.type);
      if (listeners) {
        listeners.forEach(callback => callback(message.payload));
      }
    } catch (error) {
      console.error('[BridgeService] Failed to decode message:', error);
    }
  }
}

export const bridgeService = new BridgeService();
```

### 3. Phaser Bridge Manager

**File:** `apps/game-engine/src/bridge/BridgeManager.ts`

```typescript
export class BridgeManager {
  private scene: Phaser.Scene;

  constructor(scene: Phaser.Scene) {
    this.scene = scene;
    this.setupMessageListener();
  }

  private setupMessageListener(): void {
    window.addEventListener('message', (event) => {
      const message: BridgeMessage = JSON.parse(event.data);
      this.handleMessage(message);
    });
  }

  private handleMessage(message: BridgeMessage): void {
    switch (message.type) {
      case 'INIT_GAME':
        this.initializeGame(message.payload);
        break;
      case 'START_COMBAT':
        this.startCombat(message.payload);
        break;
      // ...
    }
  }

  send(type: BridgeMessageType, payload?: any): void {
    const message: BridgeMessage = {
      type,
      payload,
      timestamp: Date.now(),
      id: this.generateId(),
    };

    // Send to React Native
    window.ReactNativeWebView?.postMessage(JSON.stringify(message));
  }
}
```

## Deep Think Additions (2025-12-28)

### GAME_READY Handshake Protocol

**Critical:** Phaser must signal it is mounted before React Native sends any data. Race conditions here are the #1 cause of "White Screen" bugs.

```typescript
// apps/mobile-shell/src/screens/BattleScreen.tsx

const BattleScreen: React.FC = () => {
  const [isPhaserReady, setIsPhaserReady] = useState(false);
  const webViewRef = useRef<WebView>(null);

  useEffect(() => {
    // Wait for Phaser to signal ready BEFORE sending any commands
    const handleReady = () => {
      setIsPhaserReady(true);
      console.log('[BattleScreen] Phaser GAME_READY received');
    };

    bridgeService.on('GAME_READY', handleReady);

    return () => {
      bridgeService.off('GAME_READY', handleReady);
    };
  }, []);

  const startCombat = async () => {
    if (!isPhaserReady) {
      console.warn('[BattleScreen] Attempted to start combat before Phaser ready');
      return;
    }

    bridgeService.send('START_COMBAT', {
      energy: energyStore.combatEnergy,
      character: userStore.selectedCharacter,
      opponent: selectedOpponent,
    });
  };

  return (
    <PhaserWebView
      ref={webViewRef}
      onReady={() => setIsPhaserReady(true)}
      onMessage={(event) => bridgeService.handleMessage(event)}
    />
  );
};
```


### iOS file:// CORS Workaround: RNFS → Bridge Injection

**Problem:** On iOS (WKWebView), `file://` access is strictly sandboxed. Loading `index.html` works, but sub-resource loading (AJAX/fetch for JSON, sprites) fails because WebKit assigns `file://` pages the Origin `null`, and CORS blocks `fetch` requests with `Origin: null`.

**Solution:** Do NOT use `fetch` inside Phaser for local data. Load assets in React Native and inject via the bridge:

```typescript
// apps/mobile-shell/src/services/assetLoader.ts
import RNFS from 'react-native-fs';
import { bridgeService } from './bridgeService';

/**
 * Load a local asset and inject it into the WebView via bridge
 */
export const injectAssetToPhaser = async (
  assetKey: string,
  filePath: string,
  frameConfig?: { frameWidth: number; frameHeight: number }
): Promise<void> => {
  // Read file as Base64 from React Native file system
  const base64Data = await RNFS.readFile(filePath, 'base64');

  // Send to Phaser via bridge
  bridgeService.send('INJECT_ASSET', {
    key: assetKey,
    data: `data:image/png;base64,${base64Data}`,
    frameConfig,
  });
};

// Usage: Load hero sprite before combat
await injectAssetToPhaser('hero', `${RNFS.MainBundlePath}/assets/hero.png`, {
  frameWidth: 32,
  frameHeight: 32,
});
```

```typescript
// apps/game-engine/src/bridge/BridgeManager.ts

private handleMessage(message: BridgeMessage): void {
  switch (message.type) {
    case 'INJECT_ASSET':
      // Load asset from Base64 data URL instead of file system
      this.scene.load.image(
        message.payload.key,
        message.payload.data
      );
      // If it's a spritesheet
      if (message.payload.frameConfig) {
        this.scene.load.spritesheet(
          message.payload.key,
          message.payload.data,
          message.payload.frameConfig
        );
      }
      break;
    // ... other cases
  }
}
```

**Problem:** Running SFX (sword hits, punches, coins) inside the WebView on Android often incurs a 100-300ms delay due to HTML5 Audio latency.

### WebView Background Throttling Warning

**Critical:** On both iOS and Android, WebView JS execution is **throttled or paused** when the app is backgrounded.

**Implications:**
- **DO NOT** run fitness accumulation logic in Phaser
- **DO NOT** run time-based resource generation in Phaser
- **DO NOT** rely on `setInterval`/`setTimeout` in WebView for critical timers

**All time-sensitive and persistent logic must run in React Native** (or Headless JS for Android).

```typescript
// WRONG: Timer in Phaser (will drift/stop when backgrounded)
this.time.addEvent({
  delay: 60000,
  callback: () => energyStore.regenerateEnergy(),
  loop: true,
});

// CORRECT: Timer in React Native
useEffect(() => {
  const interval = setInterval(() => {
    energyStore.regenerateEnergy();
  }, 60000);
  return () => clearInterval(interval);
}, []);
```

### Bridge 60FPS Trap: Command Pattern

**Problem:** Sending `UPDATE_HP` or `PLAYER_MOVED` messages every frame (16ms) will choke the bridge and cause lag.

**Solution:** Use a "Command Pattern" - React Native sends high-level commands, Phaser simulates autonomously, only results sync back:

```typescript
// WRONG: Per-frame sync (60 messages/second = bridge congestion)
update() {
  this.bridge.send('PLAYER_POSITION', { x: this.player.x, y: this.player.y });
  this.bridge.send('ENEMY_HP', { hp: this.enemy.health });
}

// CORRECT: Command pattern (1 message to start, 1 message at end)
// React Native sends:
bridgeService.send('START_COMBAT', {
  seed: 12345,  // Deterministic RNG seed for replay
  energy: 100,
  character: 'sean',
});

// Phaser simulates combat autonomously...

// Only sync RESULT back:
this.bridge.send('COMBAT_COMPLETE', {
  result: 'victory',
  energySpent: 45,
  damageDealt: 150,
  combatLog: [...], // For replay/validation
});
```

This reduces bridge traffic from ~3,600 messages/minute to ~10 messages/combat.
