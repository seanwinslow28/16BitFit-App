### Migration Summary

We successfully migrated from OpenAI's `gpt-image-1` to **Runware** (runware.ai) for DMG pixel art avatar generation.

**Why Runware?**
- Cost-effective image-to-image transformations
- HTTP REST API (simpler than WebSocket)
- Flexible model selection (can swap to pixel-art-specific models)
- No rate limiting issues during development

## Implementation Details

### 1. Edge Function: `dmg-avatar`

**File:** `supabase/functions/dmg-avatar/index.ts`

**Key Features:**
- Accepts public image URLs (from `raw-headshots` bucket)
- Calls Runware API with `runware:101@1` model
- Uses DMG-style prompts with archetype-specific snippets
- Returns generated image URL

**Request Schema:**
```typescript
interface DmgAvatarRequest {
  imageUrl: string;      // Public URL of uploaded selfie
  archetype?: string;    // "bodybuilder" | "runner" | "trainer" | "yogi" | "cyclist"
  strength?: number;     // 0..1, default 0.8 (transformation intensity)
  prompt?: string;       // Optional prompt override
}
```

**Response Schema:**
```typescript
{
  imageUrl: string;      // Runware-generated image URL
  taskUUID: string | null;
}
```

**Environment Variables:**
- `RUNWARE_API_KEY` - Set in `supabase/functions/.env` for local dev
- Production: `supabase secrets set RUNWARE_API_KEY=...`

### 2. Client-Side Integration

**File:** `apps/mobile-shell/src/services/avatarService.ts`

**Functions:**
- `generateDmgAvatar(options)` - Calls the Edge Function via Supabase client
- `getPublicHeadshotUrl(storagePath)` - Constructs public URL for uploaded images

**Usage:**
```typescript
import { generateDmgAvatar, getPublicHeadshotUrl } from '@/services/avatarService';

// Upload headshot
const uploadResult = await uploadHeadshot(photoUri, userId);

// Generate avatar
const publicUrl = getPublicHeadshotUrl(uploadResult.storagePath);
const result = await generateDmgAvatar({
  imageUrl: publicUrl,
  archetype: 'trainer',
  strength: 0.8
});

// Display avatar
<Image source={{ uri: result.imageUrl }} />
```

### 3. Image Upload Fix

**Critical Fix:** React Native's `fetch().blob()` was unreliable, causing 0-byte uploads.

**Solution:** Use `expo-file-system` to read as base64, then decode to ArrayBuffer:

```typescript
import { decode } from 'base64-arraybuffer';
import * as FileSystem from 'expo-file-system';

const base64 = await FileSystem.readAsStringAsync(imageUri, {
  encoding: FileSystem.EncodingType.Base64,
});
const arrayBuffer = decode(base64);

await supabase.storage.from('raw-headshots').upload(path, arrayBuffer, {
  contentType: 'image/png',
});
```

**Dependency Added:** `base64-arraybuffer`

## Troubleshooting Guide

### Issue: "Invalid value for 'seedImage' parameter"

**Cause:** Uploaded image is 0 bytes or inaccessible.

**Solutions:**
1. Verify `raw-headshots` bucket is public (or use signed URLs)
2. Check image upload logic uses base64 → ArrayBuffer (not fetch/blob)
3. Test image URL accessibility: `curl -I <imageUrl>`

### Issue: "Runware request failed" (400/500)

**Causes:**
- Invalid API key
- Image URL not publicly accessible
- Unsupported image format (must be PNG/JPG/WEBP)

**Debug Steps:**
1. Check Edge Function logs: `supabase functions logs dmg-avatar`
2. Verify `RUNWARE_API_KEY` is set correctly
3. Test with curl:
   ```bash
   curl -i -X POST https://YOUR_PROJECT.supabase.co/functions/v1/dmg-avatar \
     -H "Authorization: Bearer $SUPABASE_ANON_KEY" \
     -H "Content-Type: application/json" \
     -d '{"imageUrl": "https://public-url.com/image.jpg", "archetype": "trainer"}'
   ```

### Issue: Generated avatar doesn't look like pixel art

**Current Limitation:** The `runware:101@1` model is a general-purpose model, not pixel-art-specific.

**Future Improvements:**
1. **Explore Runware Model Explorer** for pixel-art-specific models
2. **Strengthen the prompt** with more specific pixel art constraints
3. **Adjust `strength` parameter** (0.9-1.0 for more stylization)
4. **Train custom LoRA** for DMG Game Boy style (future enhancement)

## Key Learnings

1. **React Native Blob Handling:** `fetch().blob()` is unreliable for file uploads. Always use `expo-file-system` with base64 encoding.

2. **Public URLs Required:** Runware (and most AI APIs) require publicly accessible image URLs. Ensure storage buckets are public or use signed URLs.

3. **Model Selection Matters:** General-purpose models like `runware:101@1` work but don't produce true pixel art. Custom models or LoRAs are needed for authentic DMG style.

4. **Prompt Engineering:** Strong, specific prompts are critical for style consistency. Include constraints like "no gradients", "blocky shapes", "4-tone palette".

5. **Iterative Approach:** Start with a working MVP (current state), then iterate on quality (model selection, prompt refinement, custom LoRA).

## 🆕 v2.0 "Smooth-to-Pixel" Architecture (December 31, 2025)

### Overview

The avatar generation system was redesigned following a comprehensive review by the BMAD Party Mode team and Gemini 3 Deep Think analysis. The new architecture addresses critical issues with the v1.0 approach:

| Issue (v1.0) | Solution (v2.0) |
|--------------|-----------------|
| AI couldn't produce true 4-color pixel art | AI generates smooth vector art; deterministic post-processing handles pixelation |
| IP-Adapter weight tradeoff (likeness vs style) | Tri-Signal Pipeline: ControlNet + IP-Adapter + Prompt working together |
| "Muddy" faces on dark/pale skin tones | CLAHE (Contrast Limited Adaptive Histogram Equalization) before dithering |
| Mobile timeouts during 15s generation | Async webhook architecture with immediate response |
| Single output with uncertain quality | "Draft Pick" UX: Two variants (Accuracy/Retro), user chooses |

### New Components

| Component | Location | Purpose |
|-----------|----------|---------|
| `generate-avatar` Edge Function | `supabase/functions/generate-avatar/` | Webhook-based async generation |
| `clahe.ts` | `supabase/functions/generate-avatar/utils/` | Contrast normalization |
| `useAvatarGeneration` Hook | `apps/mobile-shell/src/hooks/` | Client state machine |
| `AvatarBootSequence` | `apps/mobile-shell/src/components/organisms/` | Loading UX with Canny map |
| `AvatarDraftPick` | `apps/mobile-shell/src/components/organisms/` | Dual variant selection |
| `avatars` table | Supabase Database | Job tracking with Realtime |

### Model IDs (Verified December 2025)

| Component | Runware AIR ID | Purpose |
|-----------|----------------|---------|
| Base Model | `civitai:112902@354657` | DreamShaper XL Lightning Alpha 2 |
| ControlNet | `runware:20@1` | SDXL Canny (edge detection) |
| IP-Adapter | `civitai:208846@235313` | FaceID Plus v2 (likeness) |
