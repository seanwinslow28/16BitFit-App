# Story 1.5: Avatar Generation ("Smooth-to-Pixel" Architecture)

**Epic:** 1 - Foundation & Core Loop Setup
**Story Points:** 13
**Status:** 📝 Ready for Development
**Version:** 2.0

---

## User Story

**As a** new user completing onboarding,
**I want** to upload a selfie and have the system generate my personalized pixel art avatar,
**so that** I can see myself as a retro Game Boy-style character in the game.

---

## Architecture Overview

This story implements the **"Smooth-to-Pixel" strategy** designed via Gemini 3 Deep Think analysis:

- **AI generates cel-shaded vector art** (NOT pixel art)
- **Server-side processing handles pixelation** with guaranteed 4-color DMG compliance
- **Tri-Signal Pipeline** preserves likeness: ControlNet (geometry) + IP-Adapter (features) + Prompt (style)
- **CLAHE contrast normalization** prevents "muddy" output
- **Async webhook architecture** prevents mobile timeouts

## Acceptance Criteria

### AC-1: Edge Function Endpoint
- [ ] Edge function `generate-avatar` accepts `{ selfieUrl: string, userId: string }` via POST
- [ ] Returns `{ jobId: string, cannyUrl: string }` within 2 seconds
- [ ] Validates authentication via JWT
- [ ] Returns 401 for unauthenticated requests

### AC-2: Preprocessing (Boot Sequence UX)
- [ ] Runware `controlNetPreprocess` (Canny) called synchronously
- [ ] Canny map URL returned to client within 2 seconds for "Scanning Biometrics..." UX
- [ ] Canny map stored in database for client display

### AC-3: Dual Variant Generation
- [ ] Two variants generated asynchronously via Runware webhooks:
  - **Accuracy** (ControlNet weight: 0.50, IP-Adapter weight: 0.55)
  - **Retro** (ControlNet weight: 0.45, IP-Adapter weight: 0.35)
- [ ] Both variants use DreamShaper XL Lightning (`civitai:112902@354657`)
- [ ] Generation uses ControlNet SDXL Canny (`runware:20@1`)
- [ ] Generation uses IP-Adapter FaceID Plus v2 (`civitai:208846@235313`)

### AC-4: CLAHE Contrast Normalization
- [ ] CLAHE applied before Bayer dithering with parameters:
  - `clipLimit`: 2.0
  - `gridSize`: 8
- [ ] Prevents "muddy" faces on dark/pale skin tones
- [ ] Ensures full dynamic range utilization

### AC-5: DMG Palette Compliance
- [ ] Final output is exactly 128×128 pixels
- [ ] Final output contains exactly 4 DMG colors:
  - `#0F380F` (darkest)
  - `#306230` (dark)
  - `#8BAC0F` (light)
  - `#9BBC0F` (lightest)
- [ ] Bayer 4×4 dithering applied with spread factor: 45
- [ ] No gradients, anti-aliasing, or additional colors

### AC-6: Storage & Database
- [ ] Processed avatars uploaded to Supabase Storage `avatars` bucket
- [ ] Database record updated with:
  - `canny_url`: Canny edge map URL
  - `url_accuracy`: High-likeness variant URL
  - `url_retro`: High-style variant URL
  - `status`: 'processing' → 'complete' → 'failed'
- [ ] RLS policies enforce user-only access

### AC-7: Realtime Notifications
- [ ] Client subscribes to Supabase Realtime on `avatars` table
- [ ] Client receives update when each variant completes
- [ ] Client transitions to "Draft Pick" UI when both variants ready

### AC-8: Draft Pick Selection UI
- [ ] User presented with both variants side-by-side
- [ ] Variants labeled "ACCURACY" (True to you) and "RETRO" (Classic style)
- [ ] User taps to select preferred variant
- [ ] "CONFIRM SELECTION" button saves choice
- [ ] Selected variant saved as `final_url` in database
- [ ] User profile `home_avatar_url` updated with selection

### AC-9: Performance Requirements
- [ ] Total generation completes within 15 seconds
- [ ] Preprocessing returns within 2 seconds
- [ ] No mobile timeouts (async architecture)
- [ ] Edge function responds immediately after dispatching generation

### AC-10: Error Handling
- [ ] Runware API errors trigger DSP fallback (Game Boy Camera style)
- [ ] DSP fallback applies: Crop → Grayscale → CLAHE → Bayer Dither
- [ ] Timeout after 60 seconds marks job as failed
- [ ] User shown retry option on failure
- [ ] Error message logged with context

## Technical Requirements

### AI Pipeline Configuration

#### Model IDs (Verified December 2025)

| Component | Runware AIR ID | Purpose |
|-----------|----------------|---------|
| **Base Model** | `civitai:112902@354657` | DreamShaper XL Lightning Alpha 2 |
| **ControlNet** | `runware:20@1` | SDXL Canny (edge detection) |
| **IP-Adapter** | `civitai:208846@235313` | FaceID Plus v2 (likeness) |

#### Generation Parameters

```typescript
const GENERATION_CONFIG = {
  model: "civitai:112902@354657",
  steps: 4,                          // STRICT - higher causes artifacts
  CFGScale: 2.0,                     // Low CFG required for Lightning
  scheduler: "DPMPP_SDE_KARRAS",     // Lightning fails with Euler
  width: 1024,
  height: 1024,
  positivePrompt: "(flat vector art:1.4), (cel shaded:1.3), clean lines, thick outlines, retro game asset, hero portrait, green palette, minimalist, 2d, masterpiece",
  negativePrompt: "photorealistic, 3d render, noise, grain, gradient, shading, texture, messy, glitch, photography, skin pores, complex background",
};
```

#### Tri-Signal Variant Configuration

| Variant | ControlNet Weight | ControlNet End | IP-Adapter Weight | Result |
|---------|-------------------|----------------|-------------------|--------|
| **Accuracy** | 0.50 | 0.5 | 0.55 | Higher likeness, tighter structure |
| **Retro** | 0.45 | 0.4 | 0.35 | More stylized, looser interpretation |

### Post-Processing Pipeline

```
AI Output (1024×1024, smooth vector art)
    ↓
Resize (Lanczos/Bilinear → 128×128)
    ↓
CLAHE (Contrast Limited Adaptive Histogram Equalization)
    ↓
Bayer Dither (4×4 matrix, spread: 45)
    ↓
Palette Quantization (4 DMG colors)
    ↓
Final Output (128×128, exactly 4 colors)
```

### Database Schema

```sql
CREATE TABLE IF NOT EXISTS public.avatars (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  status TEXT NOT NULL DEFAULT 'processing' CHECK (status IN ('processing', 'complete', 'failed')),
  canny_url TEXT,           -- Canny edge map URL (shown during "Scanning")
  url_accuracy TEXT,        -- High-likeness variant
  url_retro TEXT,           -- High-style variant
  selected_variant TEXT,    -- 'accuracy' | 'retro' - user's choice
  final_url TEXT,           -- The chosen avatar URL
  error_message TEXT,       -- If status = 'failed'
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- Enable Realtime
ALTER PUBLICATION supabase_realtime ADD TABLE public.avatars;
```

## User Experience Requirements

### Boot Sequence Loading UX

During the 10-15 second generation time, display a themed loading sequence:

| Phase | Duration | Display | Message |
|-------|----------|---------|---------|
| 1 | 0-1.5s | Initialization animation | "INITIALIZING CARTRIDGE..." |
| 2 | 1.5-4s | Canny map (green tint) | "SCANNING BIOMETRICS..." |
| 3 | 4-12s | Progress bar + palette preview | "QUANTIZING 4-BIT COLOR..." |
| 4 | 12-15s | Completion flash | "GENERATION COMPLETE" |

**Visual Elements:**
- Canny map displayed with DMG green tint overlay
- Progress bar shows 0-75% during generation, jumps to 100% on complete
- Palette preview shows the 4 DMG colors being "loaded"

### Draft Pick Selection UX

When both variants are ready:

1. Split-screen layout showing both avatars
2. Labels: "ACCURACY" (True to you) / "RETRO" (Classic style)
3. Tap to select (highlighted border on selection)
4. "CONFIRM SELECTION" button (disabled until selection made)
5. Confirmation saves to database and transitions to Home Screen

## Async Webhook Flow

```
CLIENT (React Native)
  │
  ├─ 1. Capture selfie
  ├─ 2. Upload to temp storage
  ├─ 3. POST /generate-avatar { selfieUrl, userId }
  ├─ 4. Receive { jobId, cannyUrl } immediately (~1s)
  ├─ 5. Display cannyUrl as "Scanning Biometrics..."
  ├─ 6. Subscribe to Realtime: avatars.id = jobId
  ├─ 7. Wait for url_accuracy AND url_retro to populate
  └─ 8. Display "Draft Pick" selection UI
          │
          ▼
EDGE FUNCTION (generate-avatar)
  │
  ├─ CLIENT REQUEST:
  │   ├─ Receive selfieUrl, userId
  │   ├─ Call Runware controlNetPreprocess (SYNC, ~1s)
  │   ├─ Create DB record: status = 'processing'
  │   ├─ Fire async generation (2 variants) with webhook
  │   └─ Return { jobId, cannyUrl } immediately
  │
  └─ WEBHOOK HANDLER (called twice):
      ├─ Receive { taskUUID, imageURL } from Runware
      ├─ Parse taskUUID → jobId + variant
      ├─ Download AI image
      ├─ Resize → CLAHE → Bayer Dither
      ├─ Upload to avatars storage
      └─ Update DB: url_accuracy or url_retro
```
