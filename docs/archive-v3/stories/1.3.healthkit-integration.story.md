## Deep Think Additions (2025-12-28)

### Dual-Source Step Tracking: "Speedometer vs. Odometer" Pattern

**Use BOTH CMPedometer and HealthKit** for different purposes:

| Component | Role | Latency | Usage |
|:----------|:-----|:--------|:------|
| **CMPedometer** | "Speedometer" | < 2s | **Visual Feedback Only.** Makes the step counter tick up in real-time while user walks. Feels responsive. |
| **HealthKit** | "Odometer" | Background | **Game Economy (Source of Truth).** Awards Energy/Coins. Handles de-duplication (Watch vs. Phone). Prevents "shake to cheat." |

```typescript
// apps/mobile-shell/src/services/health/dualStepTracker.ts
import { CMPedometer } from 'react-native-pedometer';
import AppleHealthKit from 'react-native-health';

interface DualStepTracker {
  // Real-time display (CMPedometer)
  liveSteps: number;

  // Game economy (HealthKit)
  verifiedSteps: number;
  lastVerifiedAt: Date;
}

// Start CMPedometer for live UI updates
CMPedometer.startUpdates(new Date(), (data) => {
  // Update UI immediately - feels responsive
  setLiveSteps(data.numberOfSteps);
});

// HealthKit for verified steps (use for energy conversion)
const syncVerifiedSteps = async () => {
  const steps = await AppleHealthKit.getDailyStepCountSamples({
    startDate: startOfToday(),
    endDate: new Date(),
  });
  // Only award energy from verified steps
  setVerifiedSteps(steps);
};
```

### Timestamp-Based Sync (NOT Anchored Queries)

**Why NOT HKAnchoredObjectQuery?**

The Deep Think review identified that anchored queries add complexity without clear benefit for our use case. Use simple timestamp-based sync instead:

```typescript
// apps/mobile-shell/src/services/health/syncService.ts

// Store last sync timestamp in MMKV for persistence
const LAST_SYNC_KEY = 'healthkit_last_sync_timestamp';

const syncStepsWithHealthKit = async (): Promise<number> => {
  const lastSync = mmkv.getString(LAST_SYNC_KEY) || startOfToday().toISOString();
  const now = new Date();

  const options = {
    startDate: new Date(lastSync).toISOString(),
    endDate: now.toISOString(),
  };

  const steps = await AppleHealthKit.getDailyStepCountSamples(options);

  // Update last sync timestamp
  mmkv.set(LAST_SYNC_KEY, now.toISOString());

  return steps.reduce((sum, sample) => sum + sample.value, 0);
};
```

### HealthKit "Phantom Permission" Issue

**Critical Warning:** On iOS, if a user *denies* HealthKit permission, the query often returns "Success" with **0 steps** (for privacy reasons). The app might mistakenly tell the user "You haven't walked today!" instead of "Please enable permissions."

**Fix:** Always check `getAuthStatus()` explicitly BEFORE querying:

```typescript
// apps/mobile-shell/src/services/health/healthServiceImpl.ios.ts

const checkHealthKitPermission = async (): Promise<'granted' | 'denied' | 'notDetermined'> => {
  return new Promise((resolve) => {
    AppleHealthKit.getAuthStatus(
      { permissions: { read: ['StepCount'] } },
      (err, results) => {
        if (err) {
          resolve('denied');
          return;
        }
        // Check specific permission status
        const stepPermission = results.permissions.read.StepCount;
        resolve(stepPermission === 2 ? 'granted' : stepPermission === 1 ? 'denied' : 'notDetermined');
      }
    );
  });
};

const getDailySteps = async (): Promise<{ steps: number; isRealData: boolean }> => {
  // CRITICAL: Check permission status first
  const status = await checkHealthKitPermission();

  if (status !== 'granted') {
    return { steps: 0, isRealData: false };  // NOT real data - permission denied
  }

  const steps = await fetchStepsFromHealthKit();
  return { steps, isRealData: true };
};
```

### Hydration Gate Pattern

**Problem:** HealthKit queries are asynchronous and can take 500ms–2s. If the app boots and immediately initializes the Home Screen using "current" props, the user sees "0 Energy/Steps" before the query resolves.

**Fix:** Implement a "Hydration Gate" - do NOT render main content until health data is ready:

```typescript
// apps/mobile-shell/src/screens/home/HomeScreen.tsx

const HomeScreen: React.FC = () => {
  const { isHealthKitReady, dailySteps, energy } = useHealthStore();
  const [isHydrated, setIsHydrated] = useState(false);

  useEffect(() => {
    const hydrate = async () => {
      await healthStore.syncDailyData();
      setIsHydrated(true);
    };
    hydrate();
  }, []);

  // Show loading until health data is ready
  if (!isHydrated || !isHealthKitReady) {
    return (
      <View style={styles.loadingContainer}>
        <LoadingSpinner />
        <PixelText>Syncing Pedometer...</PixelText>
      </View>
    );
  }

  // Now safe to render with accurate data
  return (
    <GameBoyShell>
      <StatsDisplay steps={dailySteps} energy={energy} />
      {/* ... */}
    </GameBoyShell>
  );
};
```

This prevents the "flash of zero" issue where users see incorrect data before HealthKit responds.

## Three-Tier Permission System

To ensure all users can enjoy the app regardless of health API access, we implement a graceful degradation strategy:

### Tier Definitions

| Tier | Name | Condition | Capabilities |
|:-----|:-----|:----------|:-------------|
| **1** | Full Access | HealthKit/Health Connect granted | Auto-sync steps, workouts, calories. Best UX. |
| **2** | Manual Entry | Permission denied or unavailable | User enters steps/workouts manually. Daily cap: 15,000 steps. |
| **3** | Demo Mode | No health device / persistent denial | Fixed 100 energy/day. 5 battles/day limit. Upgrade prompts. |

> **Tier 3 Adjustment (2025-12-28):** Increased from 50 energy/3 battles to 100 energy/5 battles per PM recommendation. Rationale: Users without health devices didn't choose that limitation—lower limits felt punitive and conflicted with "Celebration Without Punishment" philosophy.

### Manual Entry Implementation (Tier 2)

```typescript
// apps/mobile-shell/src/services/manualStepEntry.ts

interface ManualStepEntry {
  steps: number;
  workoutType?: WorkoutType;
  durationMinutes?: number;
  timestamp: Date;
}

type WorkoutType =
  | 'walking'
  | 'running'
  | 'jogging'
  | 'weightlifting'
  | 'cycling'
  | 'crossfit'
  | 'yoga'
  | 'swimming'
  | 'hiit'
  | 'other';

interface ManualEntryValidation {
  maxDailySteps: 15000;
  cooldownBetweenEntries: 3600;  // 1 hour in seconds
  suspiciousPatterns: string[];
  softWarningThreshold: 3;
}

const validateManualEntry = (
  entry: ManualStepEntry,
  history: ManualStepEntry[]
): ValidationResult => {
  const flags: string[] = [];

  // Check for round number gaming
  if (entry.steps % 1000 === 0 && entry.steps > 5000) {
    flags.push('exactRoundNumbers');
  }

  // Check cooldown
  const lastEntry = history[history.length - 1];
  if (lastEntry && Date.now() - lastEntry.timestamp.getTime() < 3600000) {
    flags.push('tooFrequent');
  }

  // Check daily cap
  const todayTotal = history
    .filter(e => isSameDay(e.timestamp, new Date()))
    .reduce((sum, e) => sum + e.steps, 0);
  if (todayTotal + entry.steps > 15000) {
    flags.push('dailyCapExceeded');
  }

  return {
    isValid: flags.length < 2,
    flags,
    message: flags.length > 0
      ? "Pro tip: Syncing with your health app gives more accurate tracking!"
      : null
  };
};
```
