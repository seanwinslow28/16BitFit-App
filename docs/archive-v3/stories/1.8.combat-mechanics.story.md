## Combat Isolation Pattern

To prevent energy desync between the React Native shell and Phaser combat engine, we implement a **Combat Isolation Pattern** using a state machine.

### Problem Statement

Without isolation, this race condition can occur:
```
TIME    SHELL                 COMBAT
─────────────────────────────────────────
0ms     Energy: 100          Start Battle
50ms    Health sync: +500    [IN COMBAT]
        steps → +50 energy
100ms   Energy: 150          Use 30 energy
        (NOT VISIBLE)        for special
150ms   Combat ends          Energy: 70?
        Energy: ???          or 120???
```

### Solution: Energy State Machine

```typescript
// apps/mobile-shell/src/stores/energyStore.ts

type CombatState = 'IDLE' | 'SNAPSHOT' | 'IN_COMBAT' | 'RECONCILING';

interface EnergyState {
  // Core energy state
  currentEnergy: number;
  totalStepsToday: number;
  lastSyncedAt: Date;

  // Combat isolation
  combatState: CombatState;
  combatEnergy: number | null;         // Snapshot at combat start
  combatStartEnergy: number | null;
  pendingSteps: number;                 // Steps accumulated during combat

  // Combat timeout
  combatStartTime: Date | null;
  combatTimeoutMs: 600000;              // 10 minutes

  // Actions
  enterCombat: () => void;
  consumeEnergy: (amount: number) => boolean;
  exitCombat: (energySpent: number) => void;
  queueStepSync: (newSteps: number) => void;
  checkCombatTimeout: () => boolean;
}

const useEnergyStore = create<EnergyState>((set, get) => ({
  currentEnergy: 0,
  totalStepsToday: 0,
  lastSyncedAt: new Date(),

  combatState: 'IDLE',
  combatEnergy: null,
  combatStartEnergy: null,
  pendingSteps: 0,
  combatStartTime: null,
  combatTimeoutMs: 600000,

  enterCombat: () => {
    const state = get();
    set({
      combatState: 'SNAPSHOT',
      combatEnergy: state.currentEnergy,
      combatStartEnergy: state.currentEnergy,
      pendingSteps: 0,
      combatStartTime: new Date(),
    });

    // Checkpoint to AsyncStorage for crash recovery
    AsyncStorage.setItem('combat_checkpoint', JSON.stringify({
      combatEnergy: state.currentEnergy,
      combatStartTime: new Date().toISOString(),
    }));

    set({ combatState: 'IN_COMBAT' });
  },

  consumeEnergy: (amount: number) => {
    const state = get();
    if (state.combatState !== 'IN_COMBAT') return false;
    if (state.combatEnergy === null) return false;
    if (state.combatEnergy < amount) return false;

    set({ combatEnergy: state.combatEnergy - amount });
    return true;
  },

  exitCombat: (energySpent: number) => {
    const state = get();
    set({ combatState: 'RECONCILING' });

    // Apply combat result to base energy
    const newEnergy = state.combatStartEnergy! - energySpent;

    // Apply any steps accumulated during combat AFTER combat
    const stepsToEnergy = calculateEnergyFromSteps(state.pendingSteps);

    set({
      currentEnergy: newEnergy + stepsToEnergy,
      combatState: 'IDLE',
      combatEnergy: null,
      combatStartEnergy: null,
      pendingSteps: 0,
      combatStartTime: null,
    });

    // Clear checkpoint
    AsyncStorage.removeItem('combat_checkpoint');
  },

  queueStepSync: (newSteps: number) => {
    const state = get();
    if (state.combatState === 'IN_COMBAT') {
      // Queue for after combat
      set({ pendingSteps: state.pendingSteps + newSteps });
    } else {
      // Apply immediately
      const energyGain = calculateEnergyFromSteps(newSteps);
      set({ currentEnergy: state.currentEnergy + energyGain });
    }
  },

  checkCombatTimeout: () => {
    const state = get();
    if (state.combatState !== 'IN_COMBAT') return false;
    if (!state.combatStartTime) return false;

    const elapsed = Date.now() - state.combatStartTime.getTime();
    return elapsed >= state.combatTimeoutMs;
  },
}));
```

### Combat Timeout Implementation

```typescript
// apps/game-engine/src/scenes/BattleScene.ts

export class BattleScene extends Phaser.Scene {
  private combatTimer: Phaser.Time.TimerEvent;
  private readonly COMBAT_TIMEOUT_MS = 600000; // 10 minutes

  create() {
    // Start combat timeout timer
    this.combatTimer = this.time.delayedCall(
      this.COMBAT_TIMEOUT_MS,
      this.handleCombatTimeout,
      [],
      this
    );
  }

  private handleCombatTimeout(): void {
    // Send timeout message to RN shell
    this.bridge.send('COMBAT_TIMEOUT', {
      reason: 'timeout',
      energySpent: this.calculateEnergySpent(),
      combatDuration: this.COMBAT_TIMEOUT_MS,
    });

    // Auto-exit combat
    this.endCombat('timeout');
  }

  destroy(): void {
    this.combatTimer?.remove();
    super.destroy();
  }
}
```

## Deep Think Additions (2025-12-28)

### BigInt Fixed-Point Math: 9-Decimal Scale

**Critical:** Use BigInt with **9 decimals** (10^9 scale), NOT the original 1000n scale or 18 decimals.

**Why BigInt?**
- Floating-point math (`0.1 + 0.2 !== 0.3`) is **non-deterministic across ARM/x86**
- Combat replays must be identical on iPhone vs. Android vs. server validation
- BigInt ensures **bit-perfect determinism** across all platforms

**Why 9 Decimals (NOT 18)?**

> **⚠️ OVERFLOW WARNING (Deep Think 2025-12-28):**
> If you use 18-decimal fixed-point (standard Solidity/Ethers format where `1.0 = 10^18`):
> - `10.0` = `10,000,000,000,000,000,000`
> - **CRASH:** This exceeds MessagePack int64 max (`9,223,372,036,854,775,807`)
>
> **Use 9 decimals instead** (`1.0 = 1,000,000,000`). Safe range up to ~9 billion.

```typescript
// apps/mobile-shell/src/utils/fixedPoint.ts

/**
 * 9-decimal fixed-point math for deterministic combat calculations
 * 1.0 = 1_000_000_000n (1 billion)
 */
const SCALE = 1_000_000_000n; // 10^9

export const MathFixed = {
  // Convert number to fixed-point BigInt
  toFixed: (val: number): bigint => BigInt(Math.round(val * 1e9)),

  // Convert fixed-point BigInt back to number
  fromFixed: (val: bigint): number => Number(val) / 1e9,

  // Multiply two fixed-point values
  mul: (a: bigint, b: bigint): bigint => (a * b) / SCALE,

  // Divide two fixed-point values
  div: (a: bigint, b: bigint): bigint => (a * SCALE) / b,

  // Add (simple)
  add: (a: bigint, b: bigint): bigint => a + b,

  // Subtract (simple)
  sub: (a: bigint, b: bigint): bigint => a - b,
};

// Example: Calculate damage with 1.5x critical multiplier
const baseDamage = MathFixed.toFixed(10);     // 10_000_000_000n
const critMultiplier = MathFixed.toFixed(1.5); // 1_500_000_000n
const finalDamage = MathFixed.mul(baseDamage, critMultiplier);
// Result: 15_000_000_000n = 15.0 damage (exact, no floating-point drift)

console.log(MathFixed.fromFixed(finalDamage)); // 15
```

### MessagePack BigInt Serialization

**Critical:** `@msgpack/msgpack` does NOT handle BigInt by default. You must initialize with `{ useBigInt64: true }`:

```typescript
// Bridge serialization with BigInt support
import { encode, decode } from '@msgpack/msgpack';
import { Buffer } from 'buffer';

// Encode (RN → Phaser)
const message = {
  type: 'COMBAT_STATE',
  hp: 100_000_000_000n,  // 100.0 HP as BigInt
  energy: 45_000_000_000n,
};
const binary = encode(message, { useBigInt64: true });
const base64 = Buffer.from(binary).toString('base64');
webViewRef.current.postMessage(base64);

// Decode (Phaser → RN)
const incoming = Buffer.from(event.nativeEvent.data, 'base64');
const decoded = decode(incoming, { useBigInt64: true });
// decoded.hp is BigInt, not Number
```

### Example: Combat Damage Calculation

```typescript
// apps/game-engine/src/combat/damageCalculator.ts

interface CombatState {
  playerHp: bigint;    // Fixed-point HP
  enemyHp: bigint;
  playerEnergy: bigint;
  combo: bigint;
}

const DAMAGE_TABLE: Record<string, bigint> = {
  LP: MathFixed.toFixed(5),
  MP: MathFixed.toFixed(10),
  HP: MathFixed.toFixed(15),
  LK: MathFixed.toFixed(7),
  MK: MathFixed.toFixed(12),
  HK: MathFixed.toFixed(18),
};

const calculateDamage = (
  action: string,
  combo: bigint,
  isBlocking: boolean
): bigint => {
  const baseDamage = DAMAGE_TABLE[action] || 0n;

  // Combo multiplier: 1.0 + (combo * 0.1)
  const comboBonus = MathFixed.div(combo, MathFixed.toFixed(10));
  const comboMultiplier = MathFixed.add(SCALE, comboBonus);

  let damage = MathFixed.mul(baseDamage, comboMultiplier);

  // Block reduces damage by 75%
  if (isBlocking) {
    damage = MathFixed.div(damage, MathFixed.toFixed(4));
  }

  return damage;
};
```

## Battle Outcomes (No Defeat Philosophy)

### Core Principle

> **There is no "loss" or "defeat" in 16BitFit.**
> The user is never punished for battle outcomes.
> All outcomes are framed positively to encourage continued engagement.

### Outcome Types

```typescript
type BattleOutcome = 'victory' | 'continue_training';

interface BattleResult {
  outcome: BattleOutcome;
  xpGained: number;        // victory: calculated XP, continue_training: 0
  statsChanged: boolean;   // victory: true, continue_training: false
  avatarReaction: string;  // Pose shown on Home Dashboard
  message: string;         // Encouraging message
}
```

### Victory Outcome
- **Trigger:** Training Dummy HP reaches 0
- **XP Gained:** Based on combo count, damage dealt, time
- **Stats:** Updated (HP, ATK, DEF, SPD may increase)
- **Avatar Reaction:** Victory pose on Home Dashboard
- **Message:** "Victory! Your training paid off!"

### Continue Training Outcome
- **Trigger:** Player HP reaches 0, OR 10-minute timeout
- **XP Gained:** 0 (not negative - never punish)
- **Stats:** Unchanged (not reduced - never punish)
- **Avatar Reaction:** "Resting" pose on Home Dashboard (encouraging, not defeated)
- **Message:** "Your champion is resting... time to train more!"
